# Практическая работа №1. Декомпозиция макета CampusFlow

CampusFlow — учебный веб-сервис для студентов: найти учебное мероприятие, отфильтровать каталог, открыть подробности, добавить событие в избранное и отправить заявку на участие.

Основной сценарий: **найти → открыть → записаться → получить подтверждение → перейти в «Мои события»**.

## 1. Страницы

| №   | URL / экран                                                  | Назначение                                      | Основные блоки                                                                                                                                                                                                                                                 |
| --- | ------------------------------------------------------------ | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `/` → `index.html` (логический маршрут `/events`) — Каталог  | Найти мероприятие среди всех доступных          | Шапка (логотип, основная навигация, поиск, аватар), заголовок страницы, панель поиска и сортировки, тематические фильтры-чипы, счётчик результатов, сетка карточек мероприятий, боковая панель «Мои фильтры», пагинация                                        |
| 2   | `event.html?id=…` (`/events/:id`) — Мероприятие              | Изучить подробности и принять решение о записи  | Шапка, ссылка «Назад к каталогу», сводка мероприятия (иконка, категория, название, описание, дата, место, длительность), вкладки «Описание / Программа / Спикеры» с панелями, блок записи (счётчик и индикатор мест, «Записаться», «В избранное», организатор) |
| 3   | `register.html?id=…` (`/events/:id/register`) — Регистрация  | Отправить заявку на участие                     | Шапка, заголовок и инструкция, форма «Контактные данные» (имя и фамилия, e-mail, группа/команда, формат участия, комментарий, согласие), кнопки «Отправить заявку» / «Отмена», сообщения об ошибке, отправке и успехе                                          |
| —   | `my-events.html` (`/my-events`), `profile.html` (`/profile`) | Есть в навигации, но **не нарисованы** в макете | Вне объёма ПР №1; нужны как цели ссылок и перехода после успешной регистрации                                                                                                                                                                                  |

Vite используется в режиме многостраничного приложения (MPA): каждый экран — отдельный HTML-файл. Это проще для Vanilla JS, каждая страница работает без JavaScript и имеет собственный URL.

## 4. Семантическая структура

Выбранный экран для каркаса — **Каталог** (`index.html`): на нём больше всего повторяемых сущностей и элементов управления.

```
body
├── a.skip-link  → #main
├── header.app-header
│   ├── a (логотип → каталог)
│   ├── nav[aria-label="Основная навигация"] > ul > li > a[aria-current]
│   ├── form[role="search"] — поиск по сайту (label визуально скрыт)
│   └── a (профиль, аватар «AV»)
├── main#main
│   ├── h1 «Учебные мероприятия» + p (подзаголовок)
│   ├── form[aria-label="Поиск и сортировка мероприятий"]
│   │   ├── label + input[type=search]
│   │   ├── label + select (сортировка)
│   │   ├── button[type=reset] «Сбросить»
│   │   └── fieldset > legend «Фильтры» + radio-чипы тем
│   ├── p[role="status"] «Найдено 24 события»
│   ├── section[aria-labelledby] «Результаты» (h2 визуально скрыт)
│   │   ├── ul > li > article.event-card (h3 > a, p.tag, p > time, p.seats, button[aria-pressed])
│   │   └── div.empty-state[hidden] (h3, p, button)
│   ├── section[aria-labelledby] «Мои фильтры»
│   │   └── form: label + select «Дата», fieldset «Формат» (checkbox), fieldset «Уровень» (radio), button[type=submit] «Применить»
│   └── nav[aria-label="Страницы каталога"] > ul > li > a[aria-current]
└── footer
```

Обоснование:

- **`header`** — повторяется на всех страницах и содержит вводные элементы сайта (логотип, меню, поиск).
- **`nav`** — два набора навигационных ссылок (главное меню и пагинация), каждый получает `aria-label`, чтобы в списке landmark их можно было различить. Пагинация — `nav` со **ссылками**, а не кнопками: каждая страница результатов имеет свой URL (`?page=2`), её можно открыть в новой вкладке и отправить.
- **`main`** — один на страницу, цель ссылки «Перейти к содержимому».
- **`form` + `role="search"`** для поиска: поле работает без JS (отправка по Enter методом GET), появляется landmark «поиск». В шапке и в каталоге — две формы с разными доступными именами.
- **`fieldset` / `legend`** — группы чипов, «Формат», «Уровень»: скринридер объявляет название группы. Чипы — это `input type="radio"` (выбор одной темы, есть вариант «Все»), оформленные CSS; нативный radio даёт управление стрелками и работает без JS.
- **`section`, а не `aside`, для «Моих фильтров»:** панель — не «косвенно связанное» содержимое, а инструмент, напрямую управляющий основным списком. `aside` объявил бы её как дополнительную информацию. В DOM панель идёт после результатов, но до пагинации — так же, как читается макет слева направо.
- **`ul > li > article`** для карточек: список сообщает количество («список, 6 элементов»), а каждая карточка — самостоятельная сущность, которую можно показать и в «Моих событиях».
- **`h3 > a`** — заголовок карточки одновременно является ссылкой на страницу мероприятия: переход → ссылка. Кликабельность всей карточки делается растянутым псевдоэлементом ссылки, а не `onclick` на `article`.
- **`button[aria-pressed]`** для избранного — действие-переключатель без смены адреса. Доступное имя постоянное («В избранное: Семантический HTML»), состояние передаёт `aria-pressed`.
- **`time datetime`** — машиночитаемая дата.
- **`p[role="status"]`** — счётчик результатов объявляется скринридером после изменения фильтров без переноса фокуса.
- **`footer`** — в макете отсутствует, добавлен как рабочее допущение (см. п. 6).

Семантика остальных экранов (для следующих ПР):

- **Мероприятие:** `main` → `a` «Назад к каталогу» → `article` (всё мероприятие) → `header` статьи (`h1`, `p.tag`, `p` с `time`) → вкладки (`div[role=tablist]` + `button[role=tab][aria-selected][aria-controls]` + `div[role=tabpanel]`, переключение стрелками ←/→) → `section` «Запись на мероприятие» (`h2`, текст + `progress` для мест, `a` «Записаться», `button[aria-pressed]` «В избранное», `dl` «Организатор»). Без JS все три панели видны последовательно.
- **Регистрация:** `main` → `h1` → `form[novalidate]` (собственная валидация с сообщениями) → `fieldset` «Контактные данные» → `label` + `input` для каждого поля (`autocomplete="name"`, `type="email" autocomplete="email"`), `fieldset` «Формат участия» с radio, `textarea`, `checkbox` согласия со ссылкой на правила → `button[type=submit]` «Отправить заявку» и `a` «Отмена» (это переход назад, а не действие) → область `div[role=status]` для отправки и успеха. Ошибка поля: `aria-invalid="true"` + `aria-describedby` на текст ошибки.

## 5. Адаптивность

Макет нарисован для desktop (≈ 1440 px, контент ≈ 1040 px). Подход — mobile-first, контрольные точки 1024 / 768 / 375 px. Ни на одной ширине не допускается горизонтальная прокрутка страницы.

| Блок                       | Desktop (≥ 1200)                           | ~1024 px                                                                                         | ~768 px                                           | ~375 px                                                                                 |
| -------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------ | ------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Шапка                      | логотип, меню, поиск, аватар в одну строку | то же, поле поиска уже                                                                           | поиск сворачивается в кнопку-иконку «Поиск»       | логотип + кнопка «Меню» (`aria-expanded`), меню раскрывается списком; поиск внутри меню |
| Поиск / сортировка / сброс | в одну строку                              | в одну строку                                                                                    | поиск на всю ширину, ниже сортировка + сброс      | всё в столбец, элементы на всю ширину                                                   |
| Чипы тем                   | в строку                                   | в строку                                                                                         | перенос на 2 строки                               | одна строка с прокруткой внутри контейнера (`overflow-x: auto`), без прокрутки страницы |
| Сетка карточек             | 3 колонки + боковая панель 240 px          | 2 колонки + боковая панель                                                                       | 2 колонки, панель → диалог                        | 1 колонка                                                                               |
| Панель «Мои фильтры»       | справа, всегда видна                       | справа, уже                                                                                      | кнопка «Фильтры (N)» над списком открывает диалог | полноэкранный диалог                                                                    |
| Пагинация                  | `‹ 1 2 3 … 8 ›`                            | то же                                                                                            | то же                                             | `‹ 1 … 8 ›` + «Страница 1 из 8», зоны нажатия ≥ 44 px                                   |
| Страница мероприятия       | контент + блок записи справа               | то же, блок уже                                                                                  | блок записи переходит под сводку, до вкладок      | всё в столбец; «Записаться» закрепляется внизу экрана, пока блок записи не виден        |
| Вкладки                    | в строку                                   | в строку                                                                                         | в строку                                          | прокрутка внутри контейнера, если не помещаются                                         |
| Форма регистрации          | форма + колонка состояний                  | форма на всю ширину (колонка состояний — демонстрация; в продукте состояния появляются на месте) | одна колонка, max-width ≈ 640 px                  | одна колонка, кнопки «Отправить» и «Отмена» в столбец на всю ширину                     |

**Решение для мобильных фильтров:** на ширине < 768 px боковая панель превращается в нативный `<dialog>`, открываемый кнопкой «Фильтры (N)», где N — число применённых фильтров. Внутри та же форма, снизу закреплены «Применить» и «Сбросить». Применённые фильтры показываются над списком как чипы с кнопкой удаления. Почему: панель длинная и на телефоне вытеснила бы результаты за пределы первого экрана; `showModal()` бесплатно даёт удержание и возврат фокуса, закрытие по Esc и неактивный фон; разметка формы остаётся той же, меняется только контейнер.

## 6. Риски и вопросы к заказчику

1. **Счётчик и пагинация не согласованы:** «24 события» при 6 карточках на странице — это 4 страницы, а пагинация показывает 8. _Допущение:_ число страниц вычисляется из количества результатов; на странице 6 карточек.
2. **Две модели применения фильтров:** чипы тем, судя по всему, применяются сразу, а панель «Мои фильтры» — по кнопке «Применить». _Допущение:_ чипы, поиск (с задержкой 300 мс) и сортировка применяются сразу; панель — по «Применить»; «Сбросить» сбрасывает всё.
3. **Категория «Инструменты»** есть у карточки «Git без страха», но её нет среди чипов. _Допущение:_ чипы строятся из справочника категорий, «Инструменты» добавляется.
4. **Два поля поиска** (в шапке и в каталоге). _Допущение:_ поиск в шапке глобальный и переводит в каталог с параметром `?q=`; на странице каталога поля синхронизированы.
